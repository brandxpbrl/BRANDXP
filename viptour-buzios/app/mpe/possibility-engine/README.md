# MPE-PE-001 — Possibility Engine V0.1

## Purpose

Turn a declared current state into traceable structural possibility candidates without pretending that generated candidates are evidence, probabilities, or an exhaustive map of the future.

## First computational contract

```text
CURRENT STATE
  -> EXPLICIT OPERATORS Δ
  -> STRUCTURAL CANDIDATES
  -> VIABILITY DIMENSIONS
  -> PERTURBATION
  -> MINIMUM EXPERIMENT
  -> LEDGER
  -> EPISTEMIC UPDATE
  -> MEMORY / HERITAGE
  -> NEW STATE
```

## V0.1 laws

- MPE must never claim it found all possibilities.
- Generated candidates are not evidence.
- Probability claims require a calibrated model and an explicit validation protocol.
- Viability dimensions are qualitative until a domain-specific evaluator provides measured evidence.
- A perturbation result stays `unknown` unless an evaluator or experiment supports a stronger claim.
- A possibility cannot be promoted merely because it was generated by a model.

## Reused research principles

This architecture reuses general research patterns already present in MPE statistical-probability work: parallel scenario families, pressure/context separation, forward evaluation, negative controls, provenance, and research-only epistemic boundaries. Market-specific metrics remain in their own namespace and are not imported as general MPE truth.

It also reuses the computational idea from prior MPE morphogenesis work that state vectors can drive geometry, perturbation, attractor transitions, and multimodal representation. Geometry represents the topology of a possibility space; it does not generate scientific evidence by itself.

## Browser-first V0.1

The first public surface is `/mpe/possibility`.

It currently:

- captures objective, resources, constraints, pressures, opportunities, and unknowns;
- treats session inputs as `DECLARED`;
- applies explicit structural operators without an LLM;
- creates deterministic candidate objects;
- attaches qualitative viability dimensions with epistemic rationale;
- creates a minimum-experiment candidate;
- exposes the next planned computational layers.

Not implemented yet:

- external knowledge retrieval;
- MPE Memory retrieval;
- generative-model candidate expansion;
- domain pressure evaluators;
- possibility graph descendants;
- measured open-paths/FPI integration;
- perturbation execution;
- persistent ledger;
- geometry driven by real possibility graph state.
